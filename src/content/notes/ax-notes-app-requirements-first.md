## 글을 쓰는 곳에서, 다시 찾아오는 곳으로

AX Notes를 만들다 보니 앱도 한번 만들어보고 싶어졌다.

글을 읽고 끝나는 것에서 조금 더 나아가면 어떨까? 괜찮았던 글을 저장하고, 읽다가 떠오른 생각을 적고, 나중에 다시 찾아보는 것. 그러다가 관련 도구를 직접 써보고, 진행 중인 프로젝트도 따라가면 좋겠다.

AX Notes를 통해 AX를 소개하고, 내가 직접 만들어본 결과물을 전달하는 채널로 써보고 싶은 것이다. 내가 어떤 문제에 관심이 있고 어떻게 풀어가는지도 자연스럽게 드러날 테니 개인 브랜딩에도 의미가 있을 것 같다.

다만 앞에 두고 싶은 것은 **AX Notes가 독자에게 쓸모 있는 채널이 되는 것**이다. 내 이름을 알리는 일은 그 경험이 쌓인 다음 따라오면 좋겠다. 나중에는 광고도 붙여서 수익을 내볼 생각이다. 일단 다시 들어와서 사용할 만한 앱부터 만들어야겠지만.ㅎ

그리고 이 앱을 만드는 과정 자체를 하나의 Project로 남겨보기로 했다. 완성된 앱만 보여주는 것보다, 무엇을 생각하고 어디에서 막혔는지까지 기록하면 더 재미있을 것 같아서다.

## Codex와 먼저 정리한 것

시작은 Codex와의 대화였다.

> ax notes 앱을 만들어 보는 것은 어떨까? 앱을 만드는 과정을 글로 남기고. project 로

처음에는 독자용 앱인지, 내가 글을 작성하는 운영자용 앱인지부터 정했다. 내가 만들고 싶은 것은 **AX Notes 글을 읽는 독자용 앱**이었다. 읽기뿐 아니라 재미있는 참여 기능을 넣고, Labs와 Project를 전달하는 채널로도 써보고 싶다고 이야기했다.

그다음 앱 저장소를 상위 프로젝트의 서브모듈로 추가하고 README를 작성했다. Codex가 정리한 내용을 내가 다시 고쳤다. 처음에 이야기했던 것들을 전부 첫 버전에 넣을 필요는 없겠다는 생각이 들었다.

README의 첫 버전에는 이름도 붙였다.

> MVP 첫 번째 생존자 — 살아남기 위한 최소한의 기능

기능이 많아서 살아남는 앱이 될지, 작지만 계속 쓰게 되어서 살아남는 앱이 될지는 아직 모르겠다. 그래도 이번에는 작은 쪽으로 시작해보려고 한다.

## 첫 번째 생존자의 범위

첫 버전은 Android 앱으로 만든다. 내가 정리한 핵심은 이 정도다.

- AX Notes 글 목록과 본문 읽기
- 북마크
- 글에 연결된 메모
- 나중에 읽기 알림
- 글과 메모를 함께 찾는 검색

메모는 글에 연결된 것만 둔다. 독립적인 메모장까지 만들면 또 다른 앱이 될 것 같아서 범위를 줄였다. 읽다가 떠오른 생각을 적고, 나중에 그 글과 함께 찾아보는 정도면 된다.

계정과 백업은 만들지 않고 개인 데이터는 기기에 저장한다. 그만큼 기기를 바꾸거나 앱 데이터를 지우면 메모를 가져올 수 없다는 제약도 있다. 첫 버전에서는 이 조건을 받아들이기로 했다.

읽기 알림도 알람 시계처럼 정확한 시각에 울릴 필요는 없다. 스케줄러 수준으로, 정한 시각 이후에 다시 읽으라고 알려주면 된다.

지원 범위는 Android 8.0 이상, 첫 배포는 내부 테스트용 APK로 정했다. Labs 연결은 하고 싶은 일이지만 MVP 이후로 미뤘다. 우선 글을 읽고 저장하고 다시 찾는 흐름부터 만들어보자.

## README 다음은 PRD와 TRD

README를 수정한 다음 Codex에 이렇게 요청했다.

> readme를 내가 좀 업데이트했어. 이제 trd, prd를 작성해보자

이번 프로젝트에서는 PRD를 **무엇을 만들고 어떤 경험을 제공할지 정리하는 문서**, TRD를 **그 경험을 어떤 기술과 구조로 구현할지 정리하는 문서**로 사용했다.

PRD에는 기능 목록뿐 아니라 북마크를 해제해도 메모는 남아야 한다거나, 알림 권한을 거부해도 글 읽기는 가능해야 한다는 식으로 동작을 적었다. TRD에는 웹 콘텐츠를 가져오는 방식, 로컬 데이터 구조, 검색과 알림 처리 등을 정리했다.

기술 제안은 Kotlin과 Compose, 로컬 저장은 Room, 읽기 알림은 WorkManager다. 이 부분은 구현할 때 검토할 제안으로 남겼다. 웹에서는 앱용 정적 JSON을 제공하도록 하고, 필요하면 웹사이트 저장소도 수정하기로 했다.

문서를 받았다고 그대로 끝내지는 않았다. 메모는 글에 연결된 것만, 계정과 백업은 없음, 알림은 스케줄러 수준, 일단 APK로 내부 배포. 이렇게 내가 결정한 내용을 다시 넣고 PRD와 TRD의 설명도 맞췄다.

현재까지 정리한 문서는 아래에서 볼 수 있다. 이후 개발하면서 바뀔 수 있으므로 **이 글을 작성한 시점의 문서**를 남겼다.

- [PRD — 제품 요구사항](../../downloads/ax-notes-app/ch0/PRD.md)
- [TRD — 기술 요구사항](../../downloads/ax-notes-app/ch0/TRD.md)

여기까지가 지금 한 일이다. **Codex와 README, PRD, TRD를 작성했고 앱 코드는 아직 없다.** 앱이 실행되는 화면도, 테스트할 APK도 아직 없다.

## 이제 dots에 넘겨보려고 한다

Codex와 문서를 정리하다 보니 다음 단계도 그대로 개발해볼 수 있겠다 싶었다. 그런데 이번에는 dots에 맡겨보고 싶어졌다.

정리된 문서를 다른 도구에 넘겼을 때 얼마나 잘 이어서 개발하는지, 어느 정도까지 설명해야 하는지, 실제로 APK를 받아서 써볼 수 있을지가 궁금하다.

아직 개발을 맡긴 결과가 나온 것은 아니다. 이제 아래 프롬프트로 시작해보려고 한다. dots에는 앱 저장소인 `git@github.com:msaltnet/ax-notes.git`을 전달한다. 아래 문서 경로는 앱 저장소의 루트를 기준으로 한다. 웹사이트는 별도 저장소이므로 앱 폴더 안에 `public`이 있다고 가정하지 않도록 적었다.

```text
AX Notes Android 앱의 MVP를 개발해줘.

현재 작업 저장소는 AX Notes 앱 저장소야.
git@github.com:msaltnet/ax-notes.git

저장소 루트의 README.md, docs/PRD.md, docs/TRD.md를 읽고
구현 계획을 작성해줘. 문서의 사용자 확정 사항을 우선하고,
기술 제안은 검토해서 선택 이유를 기록해줘.

- Android 8.0 이상 지원
- Notes 목록·본문 읽기, 북마크, 글 연결 메모, 통합 검색
- 스케줄러 수준의 나중에 읽기 알림
- 계정·백업 없음
- 웹에서 제공하는 정적 JSON으로 글 목록과 본문을 가져오기
- Labs 전용 기능과 광고는 MVP 이후
- 최종 결과물은 내부 테스트용 APK

웹사이트는 별도 AX Notes Public 저장소에서 관리해.
https://github.com/msaltnet/ax-notes-public.git
앱 저장소 안에 app/, public/, inside/가 있다고 가정하지 마.
정적 JSON 제공에 필요한 웹 저장소 변경도 진행해도 돼.
웹 저장소를 수정할 때는 별도 작업 디렉터리에서 진행하고
앱과 웹의 변경 및 검증 결과를 각각 기록해줘.

웹 저장소에 접근할 수 없다면 계약에 맞는 샘플 JSON으로
앱 개발을 진행하고, 실제 웹 연동에 남은 작업을 보고해줘.

기존 미커밋 변경을 보존해줘. 앱을 검증하고, APK 빌드 결과와
실기기에서 아직 확인하지 못한 항목을 구분해 보고해줘.

개발 중 중요한 선택·문제·해결 과정은 글로 정리할 수 있도록
기록해줘. 원격 push와 배포는 별도 요청 전까지 하지 마.
```

이번에는 이 문서와 프롬프트를 가지고 실제로 시작해볼 차례다. 어떤 결과가 나올지는 다음 기록에서 이어가보려고 한다.ㅎ
